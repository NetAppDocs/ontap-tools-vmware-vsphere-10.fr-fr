= Démarrage rapide des outils ONTAP pour VMware vSphere
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Configurez les ONTAP tools for VMware vSphere avec cette section de démarrage rapide.

Commencez par effectuer ces tâches essentielles pour rendre les outils ONTAP opérationnels pour la gestion et le provisionnement du jour 0. Ensuite, effectuez les tâches optionnelles en fonction de votre environnement et de vos exigences de protection.

Dans un premier temps, vous déploierez les ONTAP tools for VMware vSphere sous la forme d’une configuration de nœud unique de petite taille qui fournit des services de base pour prendre en charge les banques de données NFS et VMFS.  Pour étendre votre configuration pour des conteneurs supplémentaires par service, une résilience améliorée ou pour utiliser des banques de données vVols et une haute disponibilité (HA), effectuez d'abord ce workflow, puis passez aux étapes d'extension. Pour plus d'informations, reportez-vous à la link:../deploy/ha-workflow.html["Workflow de déploiement de la HAUTE DISPONIBILITÉ"] .

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["Une seule"] Planification du déploiement
[role="quick-margin-para"]
Confirmez que votre environnement est prêt pour un déploiement pris en charge. Vérifiez que vos versions de vSphere, ONTAP et des hôtes ESXi sont compatibles avec la version des ONTAP tools. Allouez suffisamment de CPU, de mémoire et d'espace disque. Selon vos règles de sécurité, vous devrez peut-être configurer des pare-feu ou d'autres outils de sécurité pour autoriser le trafic réseau.

[role="quick-margin-para"]
Assurez-vous que vCenter Server est installé et accessible.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["Deux"] Déployez les outils ONTAP pour VMware vSphere
[role="quick-margin-para"]
Déployez l'appliance ONTAP tools pour établir les services de base pour les datastores NFS et VMFS.

[role="quick-margin-para"]
Dans un premier temps, vous déploierez ONTAP tools for VMware vSphere sous la forme d'une configuration à nœud unique de petite taille. Si vous prévoyez d'étendre votre configuration pour utiliser des datastores vVols et la haute disponibilité (HA), vous le ferez une fois ce workflow terminé. Pour passer à une configuration HA, assurez-vous que l'ajout à chaud de processeurs et le branchement à chaud de mémoire sont activés.

[role="quick-margin-para"]
Lors du déploiement, examinez attentivement les champs *Personnaliser le modèle*, en particulier le nom de l'hôte, l'utilisation de l'adresse IP des ONTAP tools et les exigences DNS.

[role="quick-margin-list"]
* link:../deploy/ontap-tools-deployment.html["Déployez les outils ONTAP pour VMware vSphere"]


.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["Trois"]Enregistrez et installez le plug-in client vCenter
[role="quick-margin-para"]
Ajoutez une instance de serveur vCenter pour enregistrer le plug-in client vCenter et appliquer les privilèges et rôles requis. Lorsque vous ajoutez une instance de serveur vCenter, ONTAP tools enregistre le plug-in distant, applique les privilèges personnalisés du plug-in et de l'API, crée des rôles personnalisés et ajoute un raccourci vers le plug-in dans l'interface utilisateur vSphere.

[role="quick-margin-list"]
* link:../configure/add-vcenter.html["Ajouter des instances vCenter Server aux outils ONTAP"]


.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["Quatre"]Configurer les backends de stockage
[role="quick-margin-para"]
Connectez les ressources de stockage ONTAP pour permettre aux outils ONTAP de provisionner et de gérer les datastores. Ajoutez un backend de stockage à un cluster ONTAP. Dans les environnements mutualisés où un serveur vCenter est associé à une SVM locataire, utilisez ONTAP tools Manager pour ajouter le cluster. Associez ensuite le backend de stockage au serveur vCenter afin de créer un mappage global pour cette instance vCenter.

[role="quick-margin-para"]
Ajoutez les systèmes back-end de stockage local avec des identifiants de cluster ou de SVM à l'aide de l'interface utilisateur des outils ONTAP. Ces systèmes de stockage back-end sont limités à une seule instance vCenter. Lors de l'utilisation locale des identifiants de cluster, les SVM associés sont automatiquement mappés sur vCenter pour gérer les vVols ou VMFS. Pour la gestion VMFS, notamment SRA, les outils ONTAP prennent en charge les identifiants SVM sans avoir besoin d'un cluster global.

[role="quick-margin-list"]
* link:../configure/add-storage-backend.html["Ajout d'un système back-end"]
* link:../configure/associate-storage-backend.html["Associez le back-end de stockage à une instance vCenter Server"]

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["Quatre"] Activer la protection de synchronisation active SnapMirror
[role="quick-margin-para"]

Dans les systèmes ONTAP, associez le cluster et la SVM requis, puis configurez la protection du cluster hôte dans ONTAP tools for VMware vSphere. Cette option s'applique uniquement aux datastores VMFS.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png["Cinq"]Configurez la sauvegarde et la restauration pour votre déploiement d'outils ONTAP
[role="quick-margin-para"]
Mettez en place une stratégie de sauvegarde et de restauration pour protéger la configuration des ONTAP tools et récupérer rapidement en cas de panne.

[role="quick-margin-para"]
La sauvegarde est activée par défaut dans les ONTAP tools for VMware vSphere 10.5 et se produit toutes les 10 minutes.  Planifiez des sauvegardes de vos ONTAP tools for VMware vSphere que vous pouvez utiliser pour récupérer la configuration en cas de panne.

[role="quick-margin-list"]
* link:../manage/backup-settings.html["Modifier les paramètres de sauvegarde"]
* link:../manage/recover-backup.html["Récupérer la configuration des outils ONTAP"]
